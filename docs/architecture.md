# AI 智能牧场育种平台 · 架构设计

> 面向对象：奶牛 / 肉牛 | 部署形态：边缘 + 云端混合 | 目标：可插拔、多租户、留足后期演进空间

---

## 1. 项目定位

一个「**数据采集 → 智能感知 → 生产管理 → 遗传评估 → 育种决策**」闭环的养殖育种平台，三条业务主线：

| 主线 | 能力 | 关键产出 |
|------|------|---------|
| ① 基本管理 | 智能盘点、体尺体重、健康、发情、分娩 | 实时体征事件、预警、生产档案 |
| ② 传统育种 | 家系法、性能测定、BLUP 遗传评估、育种计划 | 系谱、近交系数、EBV、选配方案 |
| ③ 新型育种 | 基因芯片、基因组选择（GBLUP/ssGBLUP） | GEBV、参考群、SNP 质控报告 |

---

## 2. 整体分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 接入终端       Web 前端 / 移动端 / 数据大屏                     │
├──────────────────────────────────────────────────────────────┤
│ API 网关        REST (FastAPI)  +  统一鉴权 / 多租户 Middleware │
├──────────────────────────────────────────────────────────────┤
│ 业务服务层       生产管理服务 | 育种管理服务 | 基因组选择服务   │
│  (模块化应用)    perception     breeding        genomics        │
├──────────────────────────────────────────────────────────────┤
│ 遗传评估引擎     GeneticEvaluationEngine (可插拔求解器)        │
│                 BLUP / GBLUP / ssGBLUP / Bayes                  │
├──────────────────────────────────────────────────────────────┤
│ 设备数据接入层   Ingestion Gateway + 适配器插件注册表           │
│                 MQTT/HTTP/Modbus → 标准化 → 入库                │
├──────────────────────────────────────────────────────────────┤
│ 数据层          PostgreSQL(业务/谱系) + TimescaleDB(时序)       │
│                 + 对象存储(基因芯片)                             │
└──────────────────────────────────────────────────────────────┘
```

### 边缘 vs 云端职责划分

| 职责 | 边缘侧（牧场本地） | 云端侧 |
|------|-------------------|--------|
| 设备接入 | ✅ 直接连传感器/摄像头/RFID，实时采集与解析 | 汇总各牧场边缘节点数据 |
| 实时告警 | ✅ 发情/分娩/健康异常即时预警（低延迟） | 事后复核与规则下发 |
| 图像推理 | ✅ 摄像头端侧 YOLO 盘点/体尺 | 模型训练与版本分发 |
| 遗传评估 | — | ✅ BLUP/GBLUP 重计算（算力集中） |
| 数据存储 | ✅ 本地缓存 + 断点续传 | ✅ 全量长期存储与跨场分析 |

## 3. 三大模块设计

### 3.1 基本管理（感知模块 `perception`）

| 场景 | 数据源 | 处理方式 |
|------|--------|---------|
| 智能盘点 | 摄像头视频流 + RFID 耳标 | YOLO 目标检测计数，RFID 交叉校验校准 |
| 体尺测量 | 深度相机（Realsense）点云 | 关键点提取 → 体尺回归 |
| 体重测量 | 地磅/卷重秤 | 时序平滑 + 分群估重模型 |
| 健康监测 | 体温、活动量、反刍传感器 | 阈值 + 异常检测（孤立森林/LSTM）双通道 |
| 发情监测 | 活动量、爬跨行为、激素 | 活动峰值 + 行为识别 + 规则 |
| 分娩监测 | 体温、行为（弓背/尾根） | 产前体温骤降检测 + 行为预警 |

统一产出为 `AnimalHealthEvent` / `AnimalReproductionEvent`（见 5.3 事件模型）。

### 3.2 传统育种（`breeding`）

- **谱系管理**：录入/导入、环路检测、父母一致性校验、系谱树、A 矩阵与近交系数。
- **性能测定**：生长、繁殖、体型线性鉴定等性状，按品种元数据配置性状模板。
- **BLUP 遗传评估**：混合线性模型 `y = Xb + Zu + e`，估计 EBV 与遗传参数。
  - 抽象 `GeneticSolver` 接口，接入 R 生态（lme4/MCMCglmm）或 Python 数值求解。
  - 支持动物模型，为向单步法（ssGBLUP）过渡预留 H 矩阵。

### 3.3 新型育种（`genomics`）

- **SNP 质控**：call rate、MAF、HWE 检验、个体/位点过滤。
- **基因组关系矩阵 G**：VanRaden 法从芯片数据构建。
- **基因组选择**：GBLUP → **ssGBLUP**（单步法，纳入无基因分型个体，最贴合生产）。
- **参考群管理**：有表型 + 有基因型个体持续累积，支撑 GEBV 可靠性。

## 4. 扩展性设计（核心）

针对「不同养殖企业接不同传感器 / 管理系统」，平台通过以下四层机制解耦，新增企业不修改核心代码：

### 4.1 设备适配器插件机制

统一抽象 `SensorDataAdapter`（方法：`connect / collect / normalize / health_check`），每种厂商设备实现一个适配器，通过「注册表 + 配置驱动」热加载。

```
app/device_ingestion/
├── adapter_base.py          # 抽象基类 SensorDataAdapter
├── adapter_registry.py      # 适配器注册表
├── event_models.py          # 统一标准化事件模型
└── adapters/
    ├── mock_camera_adapter.py   # 摄像头 Demo
    ├── mock_rfid_adapter.py     # RFID 耳标 Demo
    └── (afimilk / scr / 海康 / 国产耳标 ... 后续按需追加)
```

### 4.2 数据标准化层

所有原始数据先落到统一事件模型，屏蔽厂商协议差异（MQTT/HTTP/Modbus）。见 5.3。

### 4.3 多租户隔离

`tenant` 维度贯穿全域，通过请求上下文注入，实现数据隔离与个性化配置。

### 4.4 元数据驱动

品种、性状、疫病、指标阈值、告警规则全部走「字典 / 配置表」，不同畜种或企业通过配置适配而非改代码。

## 5. 数据模型概览

### 5.1 核心实体（关系库）

- `animal` 动物个体：耳标号、品种、出生重、系谱指针（父/母）
- `pedigree` 谱系：个体、父、母、出生记录
- `trait_record` 性能记录：动物 × 性状 × 值 × 测定日期
- `trait` 性状字典：名称、单位、遗传力、测量方式
- `sensor_event` → 时序库

### 5.2 基因数据（对象存储 + 元数据索引）

- `genotype_sample` 基因样本：个体、芯片型号、SNP 文件路径、质控报告

### 5.3 标准化事件模型（接入层）

统一为 `SensorReadingEvent`：`device_id + metric + value + unit + timestamp + animal_id + tenant_id`，以及上层的领域事件 `AnimalHealthEvent` / `AnimalReproductionEvent`。

## 6. 技术栈

- 后端：Python 3.11 + FastAPI（贴合团队偏好）
- 遗传计算：Python（numpy/scipy）+ 可插拔 R 求解器
- 数据：PostgreSQL（业务/谱系）+ TimescaleDB（时序）+ MinIO（基因文件）
- 消息：MQTT（设备）+ 内存队列（骨架阶段可替换）
- AI：YOLO（视觉）、scikit-learn / PyTorch（异常检测与预测）
- 前端：Vue3
- 部署：Docker Compose（起步）→ K8s（演进）

## 8. 演进路线建议

1. **阶段一（本骨架）**：可运行的 FastAPI + 适配器插件机制 + 统一事件模型 + 多租户 + 遗传引擎接口。
2. **阶段二**：接入真实设备（RFID/摄像头/称重），打通「采集→入库→展示」闭环。
3. **阶段三**：实现 BLUP 动物模型真实求解，谱系与性能全链路。
4. **阶段四**：接入芯片数据，实现 ssGBLUP 与 GEBV，接入参考群。
5. **阶段五**：边缘节点打包（容器化下发），多牧场 SaaS 化运营。
